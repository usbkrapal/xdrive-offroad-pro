# Terrain Monitor / xDrive Offroad Pro — перенос в MGU

Дата начала: 17 ноября 2026. Подготовка публикации: 17 ноября 2026. Веб-интерфейс утверждён пользователем. Подпись браузерного приложения: `xDrive Offroad Pro`, без префикса модели автомобиля; основное имя `Terrain Monitor` сохраняется.

## Целевая конфигурация пользователя

Подтверждено пользователем 17 ноября 2026: BMW X7 G07 / iDrive 7, двигатель 4.4 л, MGU Store 0.9.40, mgu-render 0.6.21. Дополнительно подтверждены mgu-deploy 0.8.19, mgu-updater 0.8.45, mgu-python 1.0.3, mgu-uplink 0.7.12, app-privacy 1.7.2. Точный индекс двигателя, год, I-step и service catalog ещё не установлены. Объём двигателя не подтверждает доступность сигналов.

[Протокол mgu-render 0.6.21](https://github.com/robertnisipeanu/mgu-store/blob/fc5750a8474359ad20c1c01cf29d997ff7f2d621/native/mgu-render/PROTOCOL.md) поддерживает изображения и касания одновременно в `mgu-render/1`. В 0.1.0 принудительно выбирался upstream-диалект из-за ограничения клиента kit — это отключало сенсорные вкладки и оставляло нижнюю HMI-панель. В 0.1.1 клиент исправлен: native IMAGE 10 с premultiplied RGBA и native op18, включая изображения в слоях, повторную отправку и reconnect. Установка второго renderer не требуется; `MGU_RENDERD_PROTO=upstream` больше не нужно задавать. Его явное задание остаётся отладочным fallback без сенсорных вкладок.

## Цель первой MGU-итерации

Отдельное приложение CommonJS для Node 8.7 и iDrive 7 runtime, с пятью экранами, русскими подписями, прежними круглыми приборами, схемой агрегатов и красным миганием буксующего/притормаживаемого колеса. Модель качества сигналов, сценарии и сессионные расчёты переиспользуются из веб-прототипа. DOM/React в MGU-код не входят.

Код приложения и инструментов переноса пишет Claude CLI. ChatGPT задаёт требования, проверяет реализацию, запускает тесты, сборки и эмулятор.

## Режимы данных

- **Демо** выбран по умолчанию. Все данные синтетические, маркировка постоянная.
- **Чтение автомобиля** выбирается явно. Без событий от транспорта показывается отсутствие данных; автоматической подмены демо нет. Смена режима начинает отдельную сессию, чтобы синтетические и реальные максимумы не смешивались.
- Адаптер 0.1.1 содержит 13 интерфейсов / 19 полей: базовые данные 0.1.0, угол руля, рыскание, педаль, шины с единицами автомобиля, BDS-распределение xDrive и BDS-температура масла АКПП. Сырые wheel RPM, LaneSlope и StabilizationManagement собираются только для ограниченной диагностики, без неподтверждённых физических единиц. Подробности — SIGNALS.md.
- Тангаж/крен, высоты подвески, пробуксовка, тормозные вмешательства, HDC и другие неподтверждённые параметры остаются недоступными в режиме чтения. Наличие красивой анимации не подтверждает доступ к этим сигналам.
- Камеры в демо показывают локальные иллюстрации; в режиме чтения — отсутствие подтверждённого видеопотока. Запросы на переключение камер не добавляются.
- API адаптера ограничен подписками/чтением. Запись, UDS, CAN, routines, изменение подвески/DSC/HDC, сброс ошибок и установка на автомобиль не входят в работу.

- [Подписки](https://github.com/cauliflowermossgrape/idrive7-apps/blob/082d42d52cfaa654c1a9740e6736cbd9433c486d/kit/runtime/signals.js): ctx.signals.watch; конкретные числовые IDs генерирует SDK по каталогу устройства, приложение их не выдумывает.

Полная карта источников и ограничений остаётся в SIGNALS.md. `confirmed` означает найденную реализацию upstream, не проверку на G07 пользователя.

## Граница сборки и лицензий

Локальный исследовательский checkout не содержит oap-sdk и каталога SOME/IP конкретного автомобиля. Первая версия была только preview-сборкой. Для публикации выбран отдельный путь: полноценный OAP .tgz без BMW SDK, который mgu-deploy 0.8.19 связывает со штатным SDK на головном устройстве. Классический внешний сборщик по-прежнему требует SDK; это ограничение не относится к новому режиму Store. Никакой поддельный SDK не создаётся. Аппаратная проверка манифеста и доступных полей остаётся отдельным этапом.

Для пакета Store в vendor/idrive7-apps сохранено ограниченное MIT-подмножество runtime и инструментов сборки с закреплённого коммита; файлы и изменения перечислены в PROVENANCE.json. GPL renderer/его WASM-движок запускаются только в отдельном внешнем эмуляторе; их код и бинарники не копируются в исходный пакет приложения. Нужные атласы шрифтов включаются в пакет со своими уведомлениями UFL/OFL. Для заимствованных декодеров/API сохраняется MIT-уведомление upstream.

## Аппаратный этап после локальной проверки

Уточнить I-step и реальный service catalog; SDK на компьютер для установки через Store получать не нужно; двигатель 4.4 и версии Store 0.9.40 / renderer 0.6.21 уже указаны пользователем. На стоящем автомобиле проверить доступность, масштабы, единицы, знаки, свежесть и loss-состояния каждого поля. До этой проверки не объявлять кандидатный адаптер совместимым с G07 и не включать неподтверждённые показатели как live.

## Состав реализации

- `native/src/vehicle`: декодеры, allowlist, управление подписками и качеством.
- `native/src/model`: один источник за раз; общие сценарии и сессионная статистика.
- `native/src/render`: пять экранов, круглые приборы, анимация на шинах и узлах.
- `native/src/assets`: уменьшение PNG при сборке, ограниченный реестр изображений и текстуры приборов.
- `native/src/main.ts`, `app.ts`, `manifest.ts`: вход, HMI, настройки, манифест.
- `native/scripts`: сборка CommonJS под Node 8.7, проверка совместимости, перенос только своей папки во внешний kit.
- `native/test`: отдельные тесты данных, режимов, графики и интеграции с MIT Recorder.

Браузерные и нативные тесты запускаются отдельно. Разрешение логического canvas — 1600×520, профиль эмулятора — 1920×720. Показанная частота эмулятора на компьютере не является замером производительности MGU в автомобиле. Синтаксис понижается esbuild, встроенные API проверяются отдельно; версия 0.1.0 запускалась владельцем на MGU, а исправленная 0.1.1 требует повторной аппаратной проверки.

## Запуск внешнего эмулятора

После `npm run native:build` подготовить изолированный checkout эмулятора с **исправленными** `kit/runtime` из vendor приложения. Не подменять их старым upstream runtime. Во внешнем checkout использовать `native:stage -- --upstream <path> --preview`, затем:

```sh
MGU_EMU_PREVIEW_ONLY=1 MGU_EMU_LANGUAGE=ru node kit/tools/emu.js xdrive_offroad_pro --port 8078
```

Эмулятор — только локальная проверка; автомобиль не подключается. В native full-режиме пять вкладок и «Настройки» работают касанием, нижняя панель скрыта. Демо-пауза и новая сессия доступны в настройках. В software/upstream/standard fallback остаются HMI-кнопки и явная подпись об ограничении касаний. Системные области Back/Home не захватываются.

Шапка повторяет веб: трёхцветные наклонные полосы, основной заголовок **Terrain Monitor**, подзаголовок **xDrive Offroad Pro**. Идентификатор пакета `xdrive_offroad_pro` сохраняется для обновления установленного приложения.
