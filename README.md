# Terrain Monitor

xDrive Offroad Pro

Монитор для BMW MGU / iDrive 7: рельеф, сцепление, подвеска, системы и камеры. Русский интерфейс, круглые приборы и анимация работы привода прямо на узлах и шинах. Нативная версия для MGU и отдельный веб-прототип на React/TypeScript.

**Версия 0.1.2.** Объединённая сборка приложения и компонентов камер. Предыдущую 0.1.1 владелец проверил на G07; 0.1.2 проверена сборками и тестами на хосте разработки, но ещё не на автомобиле. Что изменилось и что проверено — [QA_CAR_FIX_0.1.2.md](QA_CAR_FIX_0.1.2.md); находки проверки 0.1.1 — [CAR_TEST_FINDINGS.md](CAR_TEST_FINDINGS.md).

## Состав 0.1.2

Три компонента MGU Store. Store ставит их вместе по зависимостям:

- **Terrain Monitor** — приложение. Требует mgu-render 0.6.21, mgu-deploy 0.8.19 и xop-camera-bridge 0.1.2.
- **xop-camera-bridge** — root-служба камер. Запускает приёмник только пока открыта страница «Камеры» и останавливает его при уходе.
- **xop-camrx** — собственный приёмник камер (GPL-3.0-or-later). Принимает видеопоток камер как ещё один получатель и отдаёт рендереру три вида: передний, левый и правый. Полный соответствующий исходник выкладывается отдельным архивом рядом с пакетом.

## Установка через MGU Store

1. Обеспечьте интернет в MGU Store (Online), автомобиль должен стоять со стабильным питанием.
2. Settings → Add source: **`usbkrapal/xdrive-offroad-pro`**.
3. Выберите **Releases**, нажмите **Check now**.
4. Откройте **Terrain Monitor → Install / Update**.
5. После первой установки компонентов камер **перезапустите головное устройство**: служба регистрируется при загрузке.

В **0.1.2**:
- обновление ставит мост и приёмник камер автоматически;
- приложение всегда показывает данные автомобиля;
- сохранённый ранее выбор «Демо» переносится на автомобиль.

Не устанавливайте автоматически сгенерированный GitHub-архив «Source code» как приложение. Пакеты не содержат BMW SDK: mgu-deploy использует штатный SDK головного устройства. Подготовлено для ID7 (MGU Store 0.9.40, mgu-deploy 0.8.19, mgu-updater 0.8.45, mgu-render 0.6.21). Совместимость с конкретной прошивкой не гарантируется. Подробнее — [PUBLISHING.md](PUBLISHING.md).

## Что показывает и как получает данные

**Без управления автомобилем.**
- Телеметрия — подписка и чтение известных полей SOME/IP.
- Дополнительно — чтение UDS 0x22 по закрытому списку блоков и идентификаторов через диагностический шлюз головного устройства. Только пока экран приложения виден.
- Записи, сессий, сброса ошибок, актуаторов, изменения подвески, DSC или HDC нет.
- «Сброс» очищает только статистику сессии приложения.

**Камеры** — единственный запрос к автомобилю, кроме чтения.
- На открытой странице «Камеры» приложение просит у блока камер обычный вид «все камеры» как непрямой клиент. Так же это делают Drive Recorder и Turn View.
- Не больше 3 попыток за 30 с.
- Штатные обзоры (парковка, камера при запуске) главнее, и чужой режим камер не переопределяется.
- При уходе со страницы приложение отпускает свой запрос.
- Вид рисуется, только пока приходят свежие кадры. Иначе — «Недоступно».

**Значения появляются, только если автомобиль их отдаёт.** Значение UDS показывается, только если блок опознан как вариант с известной схемой. Полный набор приборов не гарантируется.

Подтверждено фото 0.1.1 на G07:
- обороты, момент двигателя;
- температуры масла и ОЖ;
- ускорения, рыскание;
- педаль, угол руля;
- передача;
- давление и температура шин.

Новое в 0.1.2 (на G07 ещё не проверено):
- скорости колёс и «Δ к опорной, оценка»;
- давление ГТЦ/контуров (не вмешательство по колёсам);
- масло АКПП из блока коробки;
- блокировка заднего дифференциала: момент (статус) и заданный в Н·м, положение (без процента);
- режим движения, включая Offroad;
- «Кузов к осям» (не угол к горизонту);
- датчики высоты подвески (не высота от нормы) и уровень в трёх состояниях.

Известные ограничения:
- Абсолютные крен и тангаж к горизонту пока без источника.
- DSC/DTC/HDC читаются, но не показываются: смысл квалификаторов не опубликован.
- Нет данных для момента передней и задней оси (пока молчит BasicDataSet), процента блокировки, включённого HDC и его скорости, тормозного вмешательства по колёсам, физического проскальзывания.
- Масштабы руля и педали — лучшая оценка upstream. Причина замеченных в 0.1.1 скачков руля не доказана; подробно — в QA.

## Разработка

Доступ разработчика — только переменной окружения процесса при запуске. Ничего из этого не сохраняется.
- `XOP_DEV=diag` — лист диагностики на «Системах».
- `XOP_DEV=demo` (или `demo=<сценарий>`) — демо с меткой «ДЕМО».
- `XOP_CAM_REQUEST=off` — камеры только слушают, без своего запроса.

В обычном запуске диагностические сведения пишутся в журнал приложения, без идентификаторов автомобиля.

Нужны Node.js 22+ и Python 3. Нативный runtime и мост собираются в CommonJS, совместимый с Node 8.7. Приёмник `xop-camrx` собирается Zig 0.14.1 (см. `native/packaging/xop-camrx/SOURCE-README.md`).

```sh
npm ci
npm test
npm run native:typecheck
npm run native:test
npm run native:build
ZIG=/path/to/zig sh native/camrx/build.sh host-test   # тесты приёмника на хосте
ZIG=/path/to/zig sh native/camrx/build.sh target      # целевой xop-camrx (нужен для пакета)
npm run native:package -- --repository usbkrapal/xdrive-offroad-pro --tag v0.1.2
```

`native:package` собирает приложение, мост, наборы инструментов, архив исходников xop-camrx и каталог в `native/release/`. Без целевого `xop-camrx` он завершается ошибкой. Веб-прототип: `npm run dev`, production-сборка — `npm run build`. На MGU не нужно устанавливать Node/npm/React.
